Prototype notes

Display toggles
Structure
  • The snapshot is four counts of data already on the page — completed components (R-07) and milestone mastery levels (R-05), summed to course level. Nothing here needs a new event, timestamp or time-window query. The earlier "this week" view was dropped for exactly that reason: it would have needed component-completion timestamps that no requirement asks anyone to store.
  • Kindergarten Math is the real cartridge list you sent: 7 categories, 15 subcategories, 265 components, 44 milestones, in course order.
  • Each category is a summary card — icon, milestones mastered, progress, and Mastered / Still Learning / Not Started counts. Opening a card reveals its drawer of Completed, In Progress and To Do buckets, derived from status rather than hand-placed. Completed = Mastered. In Progress = Still Learning, scheduled today, or components already underway. To Do = untouched, capped at five.
  • Every card starts collapsed. Open one and its drawer reveals the buckets, with In Progress open and Completed and To Do closed.
  • Record mastery lives in the expanded row, not on the row itself — open a milestone, read the skills that build to it, then set the level with the current value and who set it right there. Clicking the diamond still opens the picker directly from the collapsed row.
  • The subcategory still names itself under each milestone, so the category → subcategory → component hierarchy the PRD requires stays visible even though rows are grouped by status.
  • Language Arts is placeholder shaped the same way, and the other two learners run against this same catalog with different progress. Only K Math is real.
Wired to the PRD
  • R-01 / R-02 — dashboard learner card and left-nav name both open the profile.
  • R-03 — select a run to list its components in course order with status; the milestone is excluded from that list.
  • R-04 — milestone drawn as a diamond after the components for its subcategory.
  • R-05 — select a diamond to set mastery level from the progression.
  • R-06 — dashboard prompt for milestones scheduled today, suppressed once recorded.
  • R-07 — subcategory and category rollups derive from component status.
  • R-08 — dashboard chart, percent of skills complete per course.
  • R-09 — "Milestones to Review", read-only, shows at zero.
  • NFR-02 — mastery changes attributed and timestamped.
Not built, on purpose
  • Celebration events, adaptive pathways, LOR mapping, gradebook links, learner-facing view, sharing/export.
  • Learning Evidence, Teaching Resource Guide, Planner and Switch View are layout only and say so when clicked.
Decisions to make
  • No Continue / Start action. Your earlier mock put a launch button on those rows, but launching the SM Player from the progression page isn't in this PRD — R-05 only grants mastery marking here. If launching from the progression is wanted, it's a new requirement.
  • Counting has 91 components. That is a third of the course in one subcategory. Ask LIT whether it should be split.
  • Milestone numbers are out of order in the source list — Counting runs 1, 3, 4, 5, 7, 10, 12, 34, 35, and Milestone 19 sits at the end of Equations after Milestone 36. Confirm the numbers are a global ID, not a sequence.
  • Two components appear twice — "Sort Two-Dimensional Shapes" is in both Sorting Objects and 2D Shapes. Decide whether one component can sit under two subcategories.
  • R-09 vs. the glossary — R-09 counts milestones scheduled today, the glossary counts all not-yet-Mastered. Prototype follows R-09.
  • Status wording — glossary says To Do / In Progress / Done, the mock says Not Started / In Progress / Completed. Prototype follows the mock.
